# 产品缺口与实现：P7「抄送我的」+ P8「审批类型删除」

> 对应 Figma 画板 P7（抄送我的）与 P8（审批类型配置）。两个画板此前仅有前端静态/占位实现：
> P7 后端无接口、P8 无删除接口。本文记录缺口现状、实现方案、接口定义、数据模型与验收记录。

---

## 1. 缺口现状

### 1.1 P7「抄送我的」（后端无接口）

| 项 | 现状 |
| --- | --- |
| 画板 | P7-抄送我的：列表展示「序号 / 审批标题 / 发起人 / 当前节点 / 抄送时间 / 状态」，标题可点击进入详情 |
| 缺口 | 后端无任何抄送数据源：无抄送表、无提交时选抄送人的能力、无「抄送我的」列表接口、无已读标记 |
| 影响 | 页面只能渲染空态，产品闭环断在「提交审批时可选择抄送人」这一入口 |

### 1.2 P8「审批类型删除」（无删除接口）

| 项 | 现状 |
| --- | --- |
| 画板 | P8-审批类型配置：列表行提供删除操作 |
| 缺口 | 后端 `WfApprovalDefinitionController` 无 `DELETE` 接口；前端此前以「停用」冒充删除（提示"后端暂未提供删除接口"） |
| 影响 | 删除语义缺失；草稿/废弃审批类型无法清理，编码被占位 |

---

## 2. 实现方案（决策）

### 2.1 P8 删除 = 软删除（保留审批历史）

- `wf_approval_definition` 新增 `del_flag`（0 正常 / 1 已删除），`DELETE /workflow/approval-definitions/{id}` 将 `del_flag` 置 1。
- **已产生审批单的类型拒绝删除**（`wf_approval_instance` 按 `approval_definition_id` 计数 > 0），返回错误并提示「为保证历史数据完整不可删除，可改为停用」。
- 列表 / 详情 / 发布 / 编码查重一律过滤 `del_flag = '0'`；编码可复用，历史审批单详情不受影响（审批单侧不引用 `del_flag`）。
- 前端删除被拒时引导「改为停用」（`POST /{id}/disable`），停用后历史审批单仍可查看。

### 2.2 P7 抄送 = 新表 + 提交入口 + 列表 + 已读

- 新增 `wf_approval_cc` 抄送记录表（PRD §7.7 的实现简化版）。
- 提交审批接口（`POST /workflow/approvals`）新增可选字段 `ccUserIds`（被抄送人 ID 列表，排除提交人自己）。
- 审批单落库后同步写抄送记录（同一审批单同一被抄送人去重），随后才启动 Flowable 流程（同一事务链）。
- 新增 `GET /workflow/cc/list`：当前登录用户收到的抄送列表，关联审批单 + 审批类型，返回标题 / 类型名 / 发起人 / 当前节点 / 抄送时间 / 业务状态 / 已读标记。
- 新增 `POST /workflow/cc/{id}/read`：标记已读（仅本人记录可标记，写后幂等）。
- 前端 P3 表单在「所属部门」下方新增「抄送人」多选（`/system/user/list` 用户列表，禁用本人），提交时随 `submitApproval` 携带 `ccUserIds`。
- 前端 P7 列表：未读红点 + 标题点击进详情时标记已读；对齐设计的表头列，不新增操作列。
- 说明：`wf_approval_action.action_type = CC` 已在 V2 预留，本轮只落抄送表、不写 CC 操作记录。

## 3. 数据模型（V5 迁移）

迁移脚本：`workflow-server/ruoyi-workflow/src/main/resources/db/migration/V5__cc_and_delete.sql` + `V6__code_reuse_after_delete.sql` + `V7__code_uniq_active_only.sql`

```sql
-- 7.4 抄送记录表（抄送我的）
create table wf_approval_cc (
    id                   varchar(36)  not null comment '抄送记录ID',
    approval_instance_id varchar(36)  not null comment '审批单ID',
    cc_user_id           varchar(36)  not null comment '被抄送用户ID',
    cc_by_user_id        varchar(36)  null comment '抄送发起人（提交人）',
    read_flag            tinyint      not null default 0 comment '是否已读 0/1',
    created_at           datetime(3)  not null default current_timestamp(3) comment '抄送时间',
    primary key (id),
    key idx_wf_approval_cc_instance (approval_instance_id),
    key idx_wf_approval_cc_user (cc_user_id, read_flag, created_at)
) engine = innodb default charset = utf8mb4 comment = '审批抄送记录表（P7 抄送我的）';

-- 5.1 审批类型软删除（P8）
alter table wf_approval_definition
    add column del_flag char(1) not null default '0' comment '删除标志 0正常/1已删除' after status;
```

> 字段说明：抄送表与 PRD §7.7 的差异——本轮仅支持「提交时抄送」，不涉及节点级抄送（`node_key`）与抄送消息（`message`），故未引入 `node_key / sender_user_id / receiver_user_id / message / read_status / read_at`，统一采用 `cc_user_id / cc_by_user_id / read_flag / created_at` 命名并保持幂等（同单同用户去重）。

**V6（P8 收尾 · 已废弃）→ V7（最终方案）：编码唯一性改为「仅生效行唯一」**

V6 曾尝试把唯一键调整为 `(approval_code, del_flag)` 复合键，实现软删除后编码复用；但 E2E 暴露缺陷：**重建后再次删除**会在 `(code, '1')` 上二次冲突（`Duplicate entry 'P8_DELETE_TEST-1'`）。故以 V7 函数唯一索引取代 V6：

```sql
-- V6（已废弃，被 V7 取代）
alter table wf_approval_definition
    drop index uk_wf_approval_definition_code;
alter table wf_approval_definition
    add unique key uk_wf_approval_definition_code (approval_code, del_flag);

-- V7（最终方案，MySQL 8.0.34 函数索引）
alter table wf_approval_definition
    drop index uk_wf_approval_definition_code;

create unique index uk_wf_approval_definition_code
    on wf_approval_definition ((if(del_flag = '0', approval_code, null)));
```

> 原理：`del_flag='0'` 的生效行按 `approval_code` 强制唯一；`del_flag='1'` 的历史已删除行表达式值为 `NULL`，MySQL 唯一索引允许多个 NULL，因此历史行既不占用编码，也不会与后续删除冲突（重建 → 再删除可无限循环）。`selectByCode` 仍只查 `del_flag='0'`。

## 6. 验收标准

### 6.1 P7 抄送

1. admin 在 P3 表单提交审批，选择抄送人（如 ry）→ 提交成功。
2. ry 登录进入「抄送我的」：能看到该审批单（标题 / 发起人 / 当前节点 / 抄送时间 / 状态），未读红点展示。
3. ry 点击标题进入详情 → 返回列表后该条已读（红点消失）。
4. 非抄送人（如 approver3）看不到该条抄送。
5. 同单同人重复提交不产生重复抄送记录（幂等）。

### 6.2 P8 删除

1. 新建一个草稿审批类型 → 列表删除成功，记录从列表消失（`del_flag = 1`）。
2. 删除后重新创建同编码类型成功（编码复用）。
3. 对已产生审批单的类型（如 `expense_approval`）点删除 → 后端拒绝并提示 → 前端引导「改为停用」成功，状态变 DISABLED，历史审批单仍可查看。
4. 列表 / 详情 / 发布接口不返回已删除类型。

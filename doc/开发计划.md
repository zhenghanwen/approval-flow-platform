# 四、后端开发任务分解（M1–M6）

## M1 基础工程（5 人日）

- `workflow-server` Maven 多模块骨架（PRD 2.1 十一个模块：approval-boot/common/security/identity/form/workflow/business/task/integration/notification/audit）
- Spring Boot 3.4 装配：MySQL、MongoDB 连接；Flyway 初始化 `wf_user/wf_department/wf_user_dept/wf_role/wf_user_role/wf_identity_provider`（PRD 四）
- JWT 认证 + Spring Security 过滤链；统一返回结构/异常/错误码（PRD 13）
- springdoc + OpenAPI 导出；[可选] `versions.md`
- 验收：登录拿 token → `GET /users/me`；`startProcessInstanceByKey` 最简流程可跑

## M2 动态表单（6 人日）

- `wf_form_definition/wf_form_version` + MongoDB `form_schema_versions`（PRD 5.2–5.4）：版本快照不可变，`schema_hash` 校验
- 后端字段校验协议：类型/必填/字段权限（PRD 6.3 查询投影策略：固定字段进 MySQL，动态字段第一版少量投影）
- 表单数据服务：`approval_form_data` 存取（PRD 6.2 六条数据规则）
- 外部接口配置骨架 `wf_external_api`（PRD 8）：仅"登记 + 白名单 + 测试调用"，数据源绑定渲染 M2 末期
- 验收：表单设计稿发布 → 业务员填写 → MongoDB 存 JSON、MySQL 存投影（PRD 18/第二阶段验收目标）

## M3 基础审批闭环（8 人日）—— 全项目最重里程碑

- **BPMN 生成器（核心）**：流程 JSON（节点=多实例 UserTask + completionCondition + 人员白名单/审批人规则）→ BPMN XML → 部署；`wf_workflow_definition/version`（PRD 5.5–5.6）版本快照、旧实例绑定旧版本
- `TaskAssignmentService` 审批人解析（PRD 12.2 六种来源 + 找不到人就 BLOCK 策略）
- 提交审批事务链（PRD 10.1）：Mongo 先写 → MySQL 事务（审批单+流程启动+投影+操作记录）→ 孤立数据补偿标记；幂等键 v1
- 待办/已办/我发起查询（走投影表）；同意/驳回（驳回=change-state 到申请人节点，白名单 v1）
- `wf_approval_task` 投影同步：task/activity 事件监听器
- 时间线聚合（PRD `GET /approvals/{id}/timeline`）
- 前端本轮完成流程设计器 → 提交审批 → 审批列表/详情页
- 验收：PRD 18/第三阶段闭环 + "新增简单审批不改 Java 代码"

## M4 高级审批（8 人日）—— 直接复用 M0 结论

- 转交：`setAssignee` + 候选组清理 + `wf_task_transfer`
- 加签：`addMultiInstanceExecution`（v1 并行 ALL 规则）；`wf_task_add_sign`；加签驳回策略
- 退回：`moveActivityIdTo` 白名单校验（目标=同版本 UserTask，禁止网关/并行分支内节点——B1/B2）；会签节点退回走 §3.3.2 方式二；`wf_task_return`
- 撤回/取消：`deleteProcessInstance` + 权限校验 + 投影清理
- 会签/OR 签/比例：生成器产出 completionCondition 变体
- 每项操作接入 `wf_approval_operation` 幂等记录表
- 前端：任务详情操作区（同意/驳回/转交/加签/退回/撤回按钮按权限显隐）、加签面板、退回目标选择器（读白名单接口）
- 验收：PRD 11 各节规则 + `wf_approval_task` 与引擎一致（T12 断言）

## M5 可靠与安全（6 人日）

- 幂等泛化：`wf_approval_operation` 全操作接入（PRD 7.3 唯一约束扣重）
- `wf_outbox_event` 通知可靠投递（轮询重试，PRD 16.3）
- `ConsistencyRecoveryService`：SUBMITTING 卡单扫描、投影不一致扫描、Mongo 孤立文档清理（PRD 16.4）
- 接口安全：外部接口 SSRF 防护（主机白名单+禁内网/云元数据+超时+响应大小，PRD 17.2）；资源级鉴权（审批单详情防 ID 遍历）
- 前端：管理端安全交互（草稿/发布权限、危险操作二次确认）
- 验收：PRD 18/第五阶段目标

## M6 整体验收（5 人日）

- 采购审批贯穿案例（PRD 20 末段：金额字段+供应商接口+金额分支+部门负责人+财务+转交）
- PRD 19 十八条验收清单逐项打勾
- 回归：T01–T16 + 业务 E2E
- 交付物：部署文档（本地 docker-compose：MySQL+Mongo）、README、版本 tag

# 六、工程规范与流程

1. **目录：** 后端 `workflow-server/`，前端 `workflow-web/`（现有空目录启用）；
2. **分支：** `main` 保护（PR 校验后合并）；每里程碑 `feature/m1-...` 分支；提交信息 `docs:/feat:/fix:/test:` 前缀；
3. **数据库：** 一律 Flyway 新版本脚本，禁止手改已发布脚本；
4. **测试：** 引擎相关能力必须有集成测试（M0 模式延伸到业务层）；每里程碑结束跑全量测试 + 推 GitHub；
5. **AI 结对章程：** AI 写每个符号前后按 GitNexus 规程做 impact/detect_changes 管理；实测优先于文档断言——任何与《可行性分析》矛盾的引擎行为立即更新分析文档并在 commit message 注明。

## 风险登记

| 风险 | 等级 | 缓解 |
|------|------|------|
| github.com 直连被 TLS 拦截（已确认，走代理） | 已缓解 | 本仓库已配 `http.proxy`；CI 环境（Gitee/内网 GitLab 备份可选） |
| fine-grained PAT 已明文暴露 | 高 | 仓库内禁止提交任何 token/密钥；推轮换 PAT |
